## 1. Context

On 2026-05-04, Lorena's 60-invoice batch failed 5 rows. The audit traced two of those failures to customers APEXMA01 and TOPTRA02 having `"invoice"` in their `requiredDocs` — a setting that can never be satisfied because the invoice PDF is auto-generated by QBO and never an `Attachable`.

The original Fix 3 (2026-05-05) called for *removing* the Invoice checkbox outright. This spec replaces that approach with a cleaner restructure: the "Required Documents" toggle (Send All / Require Specific) and the standalone "Invoice Only" send-method idea both collapse into a new **Custom** send method whose document picker keeps Invoice as a valid (and meaningful) checkbox.

## 2. Goal

Make the Customer Manager profile editor **one decision** instead of two nested ones. Pick a send method from the dropdown; everything else falls into place. Surface validation errors that today silently overwrite data (duplicate customer codes).

## 3. Out of scope

- **Fix 4** — Pydantic validation + CSV import error UX. Separate v2.70 spec.
- **Combined Results HUD** — Invoice Sender results-view overhaul. Separate v2.71 spec.

## 4. UX decisions (locked)

| Decision | Choice |
| --- | --- |

| Backwards compat | Customers with `sendMethod = "portal_upload"` keep working — backend dispatcher routes them as before; they just can't be assigned that method through the UI anymore (none exist today per the local backup) |

## 5. Document-fetch logic (mental model)

Two sources of truth, decided by document type:

- **Invoice PDF** — always lives in **QBO**. Auto-generated. Sent via QBO email regardless of which method/checkboxes are picked. This is why Invoice is auto-satisfied in the Custom gate.
- **POD, BL, POL, PL, DO, IT/ITE** — primary source is **TMS**. Code comment in `agent/services/job_manager/send_qbo_api.py:56-57` is canonical: *"TMS is the source of truth for supporting documents. QBO holds only the invoice PDF."* For each ticked supporting doc:
  1. If QBO already has it attached → use that.
  2. Otherwise → fetch from TMS API, upload to QBO, then send.
  3. If TMS doesn't have it either → real "POD Missing" / "BOL Missing" failure surfaced in Failed Rows.

The WO#-letter routing (X=export → BOL/POL, M=import → POD; from `reference_wo_number_routing.md`) continues to apply unchanged.

In the customer modal, watching the `#custCode` input:

## 7. Backend changes

### 7.1 Required-docs gate — auto-satisfy Invoice

In `agent/services/job_manager/send_qbo_api.py` around line 192, change the gate-input list to exclude `"invoice"`:

```python
# Old:
required_docs = [] if is_oec else customer.get("requiredDocs", [])

# New:
required_docs = (
    []
    if is_oec
    else [d for d in customer.get("requiredDocs", []) if d.lower() != "invoice"]
)
```

The invoice PDF is always sent regardless — the gate has no `Attachable` to verify against, so any `"invoice"` entry is treated as already-satisfied.

`skip_types.add("invoice")` at line 83 stays — the TMS cascade still skips invoice downloads.

### 7.2 Data migration — `migrate_invoice_to_custom`

New idempotent migration in `agent/services/database.py` (or wherever the existing migrations live — `migrations.py` per the SQLite migration done in Phase 3). Runs on agent startup.

```python
# Pseudocode
def migrate_invoice_to_custom(db, supabase):
    for store in [db, supabase]:
        for customer in store.list_customers():
            req = customer.get("requiredDocs") or []
            if any(d.lower() == "invoice" for d in req):
                if customer.get("sendMethod") not in ("qbo_invoice_only_then_pod_email", "portal_upload"):
                    store.update_customer(customer["code"], {
                        "sendMethod": "custom",
                        "requiredDocs": req,  # preserved, including "invoice"
                    })
                    log.info("Migrated %s → custom send method", customer["code"])
    # Idempotent: a second run sees the customers already in `custom` mode and skips.
```

APEXMA01 → `sendMethod="custom"`, `requiredDocs=["invoice"]` → invoice-only sender ✓
TOPTRA02 → same.

### 7.3 Send dispatcher

In `agent/services/job_manager/send_job.py` around line 304, add a branch for `"custom"`:

```python
method = customer.get("sendMethod", "email")
if method == "qbo_invoice_only_then_pod_email":
    await self._send_oec(...)
elif method == "portal_upload":
    await self._send_portal_upload(...)
else:  # "email", "custom", or unknown → standard QBO email path
    await self._send_qbo_api(...)
```

`custom` and `email` both route through the same `_send_qbo_api` path — the only difference is `custom`'s `requiredDocs` is non-empty, which the existing gate already handles. No new send function needed.

## 9. Test scenarios (manual smoke set)

Run in the packaged Electron app (per `feedback_app_not_website.md`):

1. **Open Customer Manager → Add Customer.** Dropdown shows exactly 3 options. No Portal Upload visible.
2. **Pick Standard QBO Email.** No Required Documents section. Hint text reads "Send all attachments…"
3. **Pick QBO Invoice Only + POD Email.** OEC POD Email Settings section appears. No Required Documents section.
4. **Pick Custom.** Required Documents section appears with 6 checkboxes (Invoice/POD/POL/BOL/PL/DO). Invoice is pre-checked. Helper line confirms it.
5. **In Custom, untick everything except Invoice → Save → re-open.** Saved state shows Custom + Invoice only.
6. **In Custom, tick Invoice + POD → Save → re-open.** Saved state shows Custom + Invoice + POD.
7. **Type a code that already exists in Add mode.** Red warning appears live, Save is blocked. Click "View existing →" — current modal closes, modal re-opens for that existing customer in edit mode.
8. **First-launch after upgrade.** Agent logs the migration count. Re-open APEXMA01: send method is now Custom, Invoice is ticked. Re-open TOPTRA02: same.
9. **Second-launch (idempotency).** Migration logs zero customers migrated.
10. **Send an invoice for APEXMA01 (migrated to Custom + Invoice).** Send goes through end-to-end. No "missing invoice" failure. (This is the regression-safety check for the gate filter.)
11. **Send an invoice for a Custom customer with Invoice + POD.** If POD is in QBO → send works. If POD is not in QBO but is in TMS → agent fetches + uploads + sends. If POD is in neither → "POD Missing" failure surfaces correctly.
12. **Existing portal_upload customer still works.** Manually flip a test customer's `sendMethod` to `portal_upload` in the DB; trigger a send. Routes through `send_portal.py` as before. UI still won't let you set this — that's expected.
