What's shown vs. what the real tool does

  • Type chips (Imports, Exports, Vans, Warehouse, Unknown) replace today's split between the pre-fetch chip row and post-fetch tabs. Each chip carries its WILL FETCH pill inline (orange POD, blue BL/POL, etc.) so the chip itself teaches what that type fetches — no separate summary band needed.
  • Customer dropdown is new. List populates from the manifest's unique customers, sorted A–Z.
  • Sort by column header. Click CONTAINER, INVOICE #, CUSTOMER, or STATUS to sort ascending; click again for descending; click a third time to clear. Active sort column tints orange.
  • Master checkbox (top-left of the table) checks/unchecks every visible row at once. Indeterminate dash means "some visible rows checked." So: filter to Errors → click master → all errors unchecked → switch back to All → only OK rows remain checked.
  • Removing rows from the queue: on the post-fetch view, click the Queued tab, then click the master checkbox (or uncheck rows individually). Unchecked queued rows are skipped by Resume fetch — the ↻ Resume fetch (N queued) counter updates live as you uncheck. There's no separate "Remove" button needed; the checkbox semantics handle it.
  • Status tabs only render post-fetch. Counts respect the active Type + Customer + Search filter.
  • Primary action (top right): Start fetch (N) pre-fetch · Continue to Merge (N) post-fetch. Disabled when nothing's selected.
  • Secondary actions are tab-scoped post-fetch (hybrid pattern):
    • All tab → shows everything that applies (Retry, Resume, Continue to Merge). One-click access to any action without switching tabs.
    • Errors tab → shows only ↻ Retry errors + Continue to Merge.
    • Queued tab → shows only ↻ Resume fetch + Continue to Merge.
    Both Retry and Resume fire one batched fetch job — no one-by-one glitching. They auto-hide as you uncheck their underlying rows.
  • Fetching view (the new "sim" tab) demonstrates how the fetch-in-progress state would work after the fix lands. Rows are clickable — click any one to open the read-only sidebar on the right. Sidebar shows container/INV/WO/customer/will-fetch with retry/skip/manual-upload buttons disabled until the row settles. The orange-tinted row + tiny spinner is the "in-flight" row currently being fetched. Today the same view in the real app is uncliackable; this fixes that.
  • Pre-fetch status tabs are shown but de-emphasized (Errors/Queued read as — and are non-clickable). They reserve the visual space so the toolbar doesn't jump when transitioning to post-fetch. Hover for a tooltip explaining they activate after the fetch.
  • Filter meta (right side of the filter bar) shows N of M · <filters> · X selected so you always know what's filtered and how many rides through.
  • Transitions: tbody fades opacity for 140 ms on every filter/sort change. No row flicker, no jumpy table heights.
  • Click-during-fetch (not in mockup yet): in the real app, rows are non-interactive while a fetch runs. Plan is to make them clickable but open a read-only sidebar until the row settles.
